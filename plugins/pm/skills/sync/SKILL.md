# PM Sync スキル（PM の唯一の書き込み窓口）

`/pm:init` で初期化したプロジェクト PM の **唯一の書き込み窓口**。
直近の git 活動を起点に、PM ファイル全体への更新案を `pm-agent` に作らせ、ユーザー承認後に適用する。

旧スタイルの単発書き込みコマンド (decision / done / next) はすべてこのスキルに統合された。
明示的に「これを記録して」と言わなくても、コミットメッセージや plan.md の内容から自動で拾い上げる設計。

## 引数仕様

```
/pm:sync                         # 直近 3 日分の git 活動を見て PM 更新案を生成・適用
```

引数なし固定。範囲指定 (例: 「過去 1 週間」「特定 PR」) などの拡張は将来的に検討するが、初版は一括で扱う。

## 使用エージェント

| エージェント | subagent_type | 役割 |
|---|---|---|
| PM Agent | `pm-agent` | `.pm/` `.pm-local/` を読み、git log と照合して更新案を提示 (mode=sync) |

## 前提チェック

実行前に:

1. `.pm/` または `.pm-local/` のいずれかが存在するか確認
2. **どちらも存在しない** → `/pm:init` を案内して終了:
   ```
   PM が未初期化です。先に /pm:init を実行してください。
   ```
3. git リポジトリ内で実行されているか確認
4. リポジトリでない場合は警告して終了 (sync は git 活動を起点にするため)

## 実行フロー

### Phase 1: pm-agent で更新案生成

`pm-agent` を `mode=sync` で起動。エージェントが以下を自動で行う:

1. `git log --since="3 days ago" --oneline` で直近のコミットを取得
2. `git status` と `git diff --stat HEAD~5..HEAD` で最近の変更ファイルを把握
3. `.claude/zeus/` 配下に最近の plan.md / spec.md / review-validated.md があれば読む（zeus プラグインがあれば）
4. `.pm/state.md` と照合して **4 種類の差分** を検出:
   - **完了マーク候補 (done)**: state.md の進行中タスクのうち、コミットで該当機能が入った項目
   - **state 追加候補**: state.md に無いが最近のコミットで明らかな新作業
   - **decision 追加候補**: コミットメッセージや plan.md で明示された設計判断 / 技術選定
   - **next 候補**: TODO コメント / コミット末尾の future work メモから拾った将来作業

エージェントは整形済みの「PM Sync 提案」を返す。

### Phase 2: 提案レビュー

エージェントの返答をそのままユーザーに提示する。

### Phase 3: 適用方針の確認

`AskUserQuestion` で次を確認:

- **全部適用** (Recommended): 提案を全部反映して `.pm/state.md` / `.pm/decisions.md` / `.pm/roadmap.md` を更新
- **個別に確認**: 各項目を 1 つずつ `AskUserQuestion` で yes/no（多数あると煩雑なのでデフォルトは「全部適用」）
- **適用しない**: 変更せず終了

### Phase 4: 書き込み

「全部適用」または「個別に承認された項目のみ」に対して `Edit` で書き込む。

#### 書き込み手順

| カテゴリ | 操作 | 書き込みルール |
|---|---|---|
| 完了マーク (done) | `state.md` の進行中タスクを `- [ ]` → `- [x]` に置換 + 「最近完了」セクション先頭に日付付きで追加 | 「最近完了」が 15 件超になっていたら末尾を切り詰め |
| state 追加 | `state.md` の「進行中のタスク」セクション末尾に `- [ ] <task>` 追加 | 重複チェック (既存に同名があれば skip) |
| decision 追加 | `decisions.md` の見出し直後に新エントリ挿入 | 時系列降順 (新エントリは先頭)、フォーマットは init スケルトン準拠 |
| next 追加 | `roadmap.md` の指定セクション (短期/中期/長期) 末尾に追記 | エージェントの提案で分類済み |

#### overlay マージのルール

`.pm-local/` と `.pm/` に同名ファイルがある場合の書き込み先:

- 両方ある場合: `AskUserQuestion` で確認（Recommended: team = `.pm/` 側）
- team しか無ければ team へ
- personal しか無ければ personal へ

### Phase 5: 結果報告

```
## /pm:sync 完了

- 反映項目数:
  - 完了マーク: {N} 件
  - state 追加: {N} 件
  - decision 追加: {N} 件
  - next 追加: {N} 件
- 書き込み先: {.pm/ / .pm-local/ / 両方}
- スキップ: {N} 件 (重複)

### 次のステップ

`.pm/` 配下の変更を `git add` してコミットしてください。
このスキルは自動コミットしません (CLAUDE.md ルール準拠)。
```

## 動作原則

- **PM の唯一の書き込み窓口**: ask は読み取り、init はセットアップ、sync が唯一の更新窓口
- **git ベースの自動判別**: 「これを decision として記録して」のような明示操作は不要。コミットメッセージや plan.md に書けば sync が拾う
- **自動コミット禁止**: PM ファイル更新後は `git add` までで止め、ユーザーに案内
- **ファイル全文上書きしない**: 必ず Edit で部分更新
- **既存セクション構造を尊重**: スケルトンに無い独自セクションをユーザーが追加していても消さない
- **personal overlay 優先**: 同名ファイルがあれば personal が team を上書き / 補強する
- **空 PM ファイルでも動く**: スケルトンのまま中身が空でも sync が成立する (差分なし = 提案 0 件で終了)
- **idempotent**: 同じ git 状態に対して何度 sync しても結果は同じ。重複追加しない
